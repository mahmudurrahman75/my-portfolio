# PROJECT: Build a Professional Software Engineer Portfolio Website

Act as a senior frontend engineer, UI/UX designer, and software architect. Build a complete, production-quality, static Software Engineer Portfolio Website using the existing React + Vite + JavaScript project.

Do not merely provide instructions, examples, or mockups. Implement the actual working application by creating and editing the necessary project files.

Before coding, inspect the existing project structure and dependencies. Preserve the existing React + Vite setup and build the portfolio within it.

## 1. Primary Objective

Create a premium, modern, professional portfolio website for a Software Engineer.

The website should communicate technical expertise, problem-solving ability, project experience, academic background, achievements, and professional identity.

The design should feel like a polished engineering portfolio suitable for:
- Software engineering job applications
- Recruiter and hiring manager reviews
- Internship applications
- Professional networking
- Showcasing personal and academic projects

The final result must look intentionally designed, not like a generic tutorial project or a basic template.

## 2. Required Technology Stack

Use:
- React
- Vite
- JavaScript (ES6+)
- React functional components
- React Hooks where appropriate
- React Router only if genuinely needed
- Plain CSS or CSS Modules for styling
- npm for package management

You may use Lucide React for icons and Framer Motion or Motion for subtle animations if compatible with the project. Prefer lightweight dependencies.

Do not introduce a backend, database, authentication system, API server, or unnecessary state management library.

This is a static website. All portfolio content must be loaded from local JSON files.

Use semantic HTML, reusable components, clean separation of concerns, and maintainable code.

## 3. Design Direction: Premium Dark Theme

Create a sophisticated dark interface inspired by modern developer portfolios and professional engineering websites.

Design characteristics:
- Near-black or deep charcoal background
- Slightly lighter surfaces for cards and panels
- A restrained electric blue, cyan, or violet accent
- Clear typography and strong visual hierarchy
- Generous spacing
- Subtle borders
- Refined hover states
- Consistent corner radii
- Minimal, tasteful shadows
- Smooth but restrained transitions
- A clean, grid-based layout

Suggested design tokens:

--color-bg: #0B0D12;
--color-surface: #121620;
--color-surface-elevated: #191F2B;
--color-text-primary: #F4F6FA;
--color-text-secondary: #A3ADBD;
--color-accent: #6EA8FE;
--color-border: #273041;

Define all design tokens as CSS custom properties in a central stylesheet. Use them consistently throughout the application.

The colors are starting points, not rigid constraints. Refine the palette to achieve a cohesive visual result.

Typography:
- Use a modern, readable sans-serif font.
- Consider Inter or a similar font.
- Use monospace typography sparingly for code-related details, labels, and technical accents.
- Maintain accessible text contrast and comfortable line heights.

Avoid:
- Excessive gradients
- Neon overload
- Overuse of glassmorphism
- Excessive animations
- Large numbers of decorative elements
- Generic emoji icons
- Inconsistent spacing
- Overly rounded cards everywhere
- Fake terminal animations that distract from the content

## 4. Website Architecture

Build the website as a single-page portfolio with clearly defined sections.

Required sections, in this order:

1. Navigation
2. Hero / Introduction
3. About Me
4. Technical Skills
5. Featured Projects

A separate résumé page is not required. Provide a résumé download link in the hero and contact areas if a résumé asset is available.

All personal and portfolio content must be stored in separate JSON files. React components must not contain hardcoded personal information, project descriptions, academic details, skills, experience records, achievements, or contact information.

Do not use fetch() to load these local JSON files. Static imports are more suitable for this Vite application.

The website must work without an API, backend, database, or runtime network request for portfolio content.

## 21. Data-Driven Rendering Rules

This requirement applies across every section.

1. All portfolio content comes from the JSON data layer.
2. React components are responsible only for layout, presentation, and interaction.
3. Repeated items are rendered from arrays using map().
4. Optional fields are conditionally rendered.
5. Empty arrays are handled gracefully.
6. IDs or stable keys are used for repeated records.
7. JSON files must be valid JSON, not JavaScript objects.
8. No personal data is duplicated unnecessarily across files.
9. Navigation configuration must correspond to actual sections.
10. The README must explain where each type of content is maintained.

Do not place personal data inside component constants as a workaround.
